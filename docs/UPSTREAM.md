# Upstream: Librelancer

OpenLancer uses [Librelancer](https://github.com/Librelancer/Librelancer) as a git submodule at `external/Librelancer`.

## Rules

- The submodule stays pinned to an upstream commit. OpenLancer code lives in OpenLancer's own projects.
- A fix that must go into Librelancer itself is a local patch in `patches/librelancer/`. `tools/apply-librelancer-patches.ps1` applies the patches to the submodule working tree. Do not edit the submodule by hand, and do not commit inside it.
- The local patches are never submitted upstream. Librelancer does not accept AI-written issues or pull requests, and automated tools must not open them.

The patches are a stack. Each patch applies on top of all patches before it in name order, and it can change lines that an earlier patch added. Make each new patch on top of all earlier patches. In a temporary index, the script calculates the expected tree after each prefix of the stack: no patch, 0001, 0001-0002, and so on. It compares the working tree with each of these trees on all paths that the patches touch. Then it applies only the patches after the matching prefix.

Use `-Check` to see the state of each patch ("applied" or "missing") without a change. When the working tree matches no prefix, the script stops and names the files that are different. ## Build the submodule

1. In the repo root, run `powershell -ExecutionPolicy Bypass -File tools\apply-librelancer-patches.ps1`.
2. In `external/Librelancer`, run `powershell -ExecutionPolicy Bypass -File .\build.ps1 --assemblyversion 0.0.0-ol GenerateVersion BuildNatives ShaderDependencies`.
3. Open PowerShell in the repo root.
4. Run `dotnet build OpenLancer.slnx`.
5. To get the game and the editor, run `dotnet build external\Librelancer\src\lancer\lancer.csproj` and `dotnet build external\Librelancer\src\Editor\LancerEdit\LancerEdit.csproj`.

### Known issue: `BuildAll` fails when the path has a space

The `BuildEngine` and `BuildSdk` targets publish with `UseArtifactsOutput=true`. The intermediate path is then absolute. `Shader.targets` passes it to `LLShaderCompiler` as `--rsp $(IntermediateOutputPath)...` without quotes. A space in the path, such as in `Freelancer Decompiled`, splits the argument, and the shader step fails. A normal `dotnet build` uses a relative `obj\` path and is not affected. The correct fix is to quote the argument in upstream `Shader.targets`. A person must write that fix by hand.
